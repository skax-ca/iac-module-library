# 세션 기록 규칙 (5개 저장소 공용)

세션은 이 저장소에서 열고 배포·GitOps 저장소 4개를 `--add-dir`로 붙인다. `.claude/session.md`는
**이 저장소 것 하나**가 5개 저장소의 기억이고, 형제 저장소에는 session.md를 두지 않는다.
전역 session-start·session-end 스킬의 두 절(`지난 세션`·`다음 할 일`)에 더해 아래 절을 갖는다.

## `## 저장소 상태` 절

`지난 세션` 앞에 둔다. 열은 `repo | git | 상태`. 행은 형제 4개(`eks-reference-infra`·
`eks-platform-gitops`·`aks-reference-infra`·`aks-platform-gitops`, 경로는 `../<repo>`).

- `git`: 브랜치와 원격 차이·미커밋 수를 한 토막으로(`main = origin`, `main = origin +1 미푸시`,
  `feat/x, 미커밋 2`).
- `상태`: 인프라 구축·철거 여부와 그 저장소의 다음 작업이 전제하는 사실 한 줄. 커밋 메시지가
  이미 갖는 작업 서술은 쓰지 않는다. 코드·README·워크플로에서 읽히는 사실(라이선스·모듈 태그·
  provider 버전·CI job 구성)도 쓰지 않는다. 캐시가 원본과 갈리는 순간 틀린 쪽이 여기다.

⛔ 표 아래에 gotcha 문단을 쌓지 않는다. 운영 절차는 그 repo의 `docs/runbooks.md`, 배포 루트
공통 함정은 `CLAUDE.md` 「배포 루트 공통」, GitOps 규약은 그 repo `README.md`가 갖는다. 이 파일은
세션마다 덮어써서, 여기에만 있는 지식은 언젠가 사라진다.

## 세션 시작 (스킬 3단계에 추가)

표의 각 repo에서 `git status -sb | head -1`과 `git status --short | wc -l`을 찍어 `git` 열과
대조한다. 어긋나면(다른 세션이 커밋·전환했거나 미커밋이 남았으면) 표를 고치지 말고 사용자에게
알린다. 표는 캐시이고 실물이 우선이다.

## 세션 종료 (스킬 1·2·4단계에 추가)

- 1단계 변경 확인 대상에 표의 repo 4개를 포함한다.
- 2단계에서 덮어쓸 때 `## 저장소 상태` 표를 보존하고 `git` 열을 실물로 갱신한다. `상태` 열은
  이번 세션에 바뀐 사실만 고친다.
- 4단계 커밋·푸시 대상에 변경이 있는 형제 repo를 포함한다. 형제 repo의 문서 전용 변경은 그
  repo 규칙대로 main 직접 커밋이다.

## `## 다음 할 일`에 두는 것

판정은 **"이 항목을 지워도 문서를 따라가면 같은 일이 일어나는가"** 하나로 한다. "예"면 두지 않는다.
절차서를 옮겨 적은 항목은 원본이 바뀌어도 따라 바뀌지 않아, 원본과 갈리는 순간 틀린 쪽이 여기다.

| 둔다 | 두지 않는다(자리) |
|------|------------------|
| 진행 중인 작업의 위치: 절차서 절을 가리키는 **한 줄** | 절차 단계(그 repo `docs/*-lifecycle.md`·`runbooks.md`) |
| 사용자 결정 대기 | 실측 전 항목(문서의 ⏳ 표시. 할 일에는 "⏳를 걷는다" 한 줄만 둔다) |
| 문서에 자리가 없는 결함·관찰 | 사건에 반응하는 대응(증상이 났을 때 여는 문서: `runbooks.md`·「자주 막히는 지점」·`CLAUDE.md`) |
| `.local/` 작업(발표 등) | 규칙이 이미 정한 릴리스 절차(`docs/conventions.md`·`CLAUDE.md`) |
| | CI가 스스로 도는 검사(실패하면 run이 알린다) |
| | 기각 기록(`docs/decisions.md`, 패턴 문서 「하지 않는 것」, 모듈 README) |

- 문서에 자리가 있는데 아직 안 적힌 지식은 할 일로 남기지 않고 **그 세션에 문서로 옮긴다**.
- 항목은 `- [ ] [repo] 할 일 (MM-DD~)` 한두 줄에 근거 위치(파일 경로)를 붙인다. 근거·배경 본문은 쓰지 않는다.
  `[repo]`는 `[module]`·`[eks-ref]`·`[aks-ref]`·`[*-gitops]`·`[local]`이고 어느 저장소 일인지만 말한다.
- 행동이 없는 메모("그대로 두었다")는 두지 않는다. 끝난 항목은 지운다.

### 소절 두 개

| 소절 | 무엇이 들어가나 |
|------|----------------|
| `### 지금` | 지금 착수할 수 있는 것. 다가오는 구축·철거의 절차서 포인터도 여기다 |
| `### 조건이 오면` | 관찰 가능한 사건이 와야 열리는 것. `조건: 할 일` 형식으로 쓴다 |

- 조건은 **관찰 가능한 사건**이다. "판단한다"로 끝나면 무엇이 오면 판단하는지를 적거나 지운다.
- `(MM-DD~)`는 등록일이다. 세션 종료 때 60일 넘은 `조건이 오면` 항목은 **유지·문서로·삭제** 중
  하나를 사용자에게 묻는다.

## `다음 할 일` 표시 (세션 시작 3단계·세션 종료 5단계)

소절은 `A.` `B.`로, 항목은 소절과 무관하게 **전체에서 1부터 이어지는 번호**로 표시한다("3번 하자"로
고르기 위해서다). 표시할 때만 바꾸고 파일의 `- [ ]`는 그대로 둔다.
