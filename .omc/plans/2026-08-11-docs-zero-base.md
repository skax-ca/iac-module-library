## 2. 설계 원칙 (새 문서 집합이 지킬 것)

| # | 원칙 | 강제 방법 |
|---|---|---|
| P1 | **독자로 파일을 가른다** — 주제가 아니라 | 파일마다 첫 줄에 "이 문서를 읽는 사람" 명시 |
| P2 | **변경 이력을 본문에 쓰지 않는다** | 이력은 `CHANGELOG.md` 1개 + git history |
| P3 | **이모지는 표의 상태 열 3종만** (`✅ ⏳ ❌`) | 본문 이모지 0개. 강조는 볼드, 주의는 인용 블록 |
| P4 | **한 문서는 400줄을 넘지 않는다** | 넘으면 독자가 갈린 것 — 파일을 나눈다 |
| P5 | **선택은 표로, 절차는 명령으로** | 산문으로 고르게 하지 않는다 |
| P6 | **문서 간 링크는 문서 단위** | "절 번호까지 써야 인용 가능"한 문서를 만들지 않는다 |
| P7 | **정정 서술을 남기지 않는다** | *"초판이 틀렸다"* 는 git이 안다. 문서는 **현재 사실만** 진술 |

> P7이 이번 재작성의 핵심이다. 현재 문서가 장황한 1차 원인은 분량이 아니라
> **"만들어 가는 과정"이 결과물에 섞여 있는 것**이다.

### 3.1-1 왜 `04-teardown.md` 가 독립 문서인가 (2026-08-11 사용자 제안)

**초판은 이것을 `06-runbooks.md` 의 한 절로 잡았다. 틀렸다.**

1. **삭제는 생성의 역순이 아니다.** `tofu destroy` 는 **IaC 밖에서 생긴 것을 모른다** —
   Karpenter 노드 · ALBC 의 ALB/TargetGroup · `crds.keep: true` 가 남긴 CRD · VPC CNI 의 ENI.
   ⇒ teardown 은 역순 표 하나가 아니라 **선처리 단계를 가진 독립 절차**다.
2. **분량** — teardown 만 100~150줄. runbooks 와 합치면 350줄로 **P4(400줄 상한)에 육박**한다.
3. **검색성** — 철수는 **급하게** 일어난다(계약 종료·비용 이슈·사고). 파일명에 없으면 못 찾는다.
4. **계약 요건** — 이 repo 의 산출물은 *"고객사에 배송되는 계약"*(CLAUDE.md)이다.
   컨설팅 자산은 **반드시 철수**한다. 철수 절차 부재의 대가:
   - 비용: NAT GW 는 트래픽 0 이어도 **AZ당 월 ~$43**(`10` 열린 항목 9 실측).
     EKS 컨트롤 플레인은 노드 0대여도 과금된다.
   - 보안 표면: 방치된 IAM Role · OIDC 신뢰 정책 · SG
5. 🔴 **공용 계정에서 삭제가 가장 위험한 작업이다.** 실측: VPC 27개 · 남의 EKS 2개.
   **생성은 잘못해도 내 것만 늘지만, 삭제는 잘못하면 남의 것이 사라진다.**
   ⇒ 생성 절차보다 **더 엄격한 문서**가 필요하다.
6. **부분 삭제가 전체 철수보다 흔하다** — GitOps 만 걷어내기 · 노드만 줄이기 ·
   환경 하나만 지우기 · 야간 정지. 현재 문서에 **어느 것도 없다.**

⭐ **03 옆에 04 를 두는 것이 설계다.** 생성 문서를 읽는 사람이 바로 옆에서
*"그리고 어떻게 걷어내는가"* 를 본다 — 라이프사이클이 한 쌍으로 보인다.

#### `04-teardown.md` 구성

```
1. ⛔ 시작 전 확인 — 공용 계정에서 태그로 특정하는 법
2. 삭제 순서 (역순이 아니다 — IaC 밖 자원 선처리)
3. 부분 삭제 시나리오 4개 (GitOps만 / 노드만 / 환경 하나 / 야간 정지)
4. 🔴 되돌릴 수 없는 것 목록
5. 잔존물 체크리스트 (비용이 계속 나는 것 우선)
6. 자주 막히는 지점 (ENI 로 VPC destroy 멈춤 등)
```

#### `scripts/teardown-verify.sh` — 삭제는 사람이, 검증은 기계가

| 역할 | 누가 | 근거 |
|---|---|---|
| **삭제 실행** | **사람** (`tofu destroy`) | ⛔ 자동화하지 않는다 |
| **잔존물 탐지** | **기계** | *"27개 VPC 중에서 눈으로 찾기"* 는 사람이 하기 가장 나쁜 일 |

> ⛔ **teardown 을 스크립트로 자동화하지 않는 것은 의도된 결정이다.**
> `bootstrap.sh` 는 만드는 스크립트라 **멱등성이 안전망**이지만, teardown 은 그렇지 않다 —
> 두 번 돌려도 안전한 게 아니라 **한 번만 잘못 돌려도 끝**이다. 공용 계정에서는 특히.
> ⇒ `bootstrap/verify.sh` 의 **거울**만 만든다(그쪽은 drift 주입 음성 테스트까지 있다 — `README:113`).

## 5. ★ `07-decisions.md` — zero-base에서 지식을 잃지 않는 유일한 장치

현재 문서에 **결정 ID가 93개**(`D-ENGINE` … `D31`) 있다. 대부분은 이미 코드·설계에
반영돼 있어 **별도 기록이 불필요**하다. 살려야 하는 것은 **"기각된 안"** 뿐이다 —
그것만이 문서를 지우면 사라지고, 사라지면 **6개월 뒤 누군가 다시 제안한다.**

예상 항목 (~15개, 각 1~2줄):

| 하지 말 것 | 이유 (한 줄) |
|---|---|
| Terraform + OpenTofu 동시 지원 | 실측 비용 5건으로 기각 (`04 §3`) |
| eksctl 도입 | IaC 소유 경계를 깬다 (`22 §1.1`) |
| 전 모듈 `1.0.0` 일괄 컷 | 컴포넌트별 churn 속도가 다르다 (`05 §4`) |
| self-managed에서 CodeConnections | argo-cd v3.5.0 지원 0건 |
| `argocd --core` 로 비밀번호 변경 | 세션 토큰이 없다 (`23 §2.3-1`) |
| `ignoreDifferences` 로 OutOfSync 해소 | `ServerSideDiff=true` 가 정답 (D-SSDIFF) |
| root App 훑기를 `exclude` 로 제외 | 자기소멸 데드락 (D-ROOTAPP-SKIP) |
| inline SG rule | 별도 리소스로 분리 (`03 §2.1`) |
| `terraform_remote_state` 참조 | 결정적 네이밍 + `data` 조회 |
| 문서를 경로별로 복제 | drift (`21 §1.7`) |
| … | (재작성 시 전수 추출) |

> **이 표가 없으면 zero-base는 지식 손실이다.** 있으면 손실이 아니라 **압축**이다.

### 6.1 왜 실증 재구축이 필요한가

1. **생성 절차는 한 번도 실행된 적이 없다.** 현재 인프라는 ~2주에 걸쳐 **증분으로** 섰다.
   문서는 *"도달한 상태"* 를 기술하지 *"0에서 시작하는 순서"* 를 기술하지 않는다.
2. **순서 의존이 실재한다는 증거가 이미 있다** —
   `iac-reference-infra/bootstrap/README.md:88` 「3. 순서가 자유롭지 않다 (실측)」.
   부딪혀서 알아낸 것이고, 같은 종류가 L1~L3에도 있을 것이다.
3. **선례**: `scripts/argocd-seed.sh:271` 의 빈칸은 *"완료 조건을 실제로 실행했기 때문에"* 발견됐다
   (2026-08-11). 규모만 다르고 같은 메커니즘이다.

**⭐ 순서를 뒤집는다 — 문서가 테스트 대상이고 재구축이 테스트 실행이다.**

```
Wave 3 초안 작성  →  Wave 4 그 초안만 보고 재구축  →  Wave 5 실패 지점 = 문서의 빈칸
     (가설)               (실험)                        (수정)
```

⛔ **절차서 없이 먼저 지우지 않는다.** 그러면 재구축이 "문서 집필"이 아니라 **고고학**이 되고,
배우는 것이 *"절차가 맞는가"* 가 아니라 *"내가 무엇을 찾아봐야 했는가"* 가 된다.

### 6.2 Wave 4 실증 — 범위와 절차

**범위: L1~L3** (사용자 확정 2026-08-11). L0(부트스트랩)는 **유지**한다 —
`verify.sh` 음성 테스트까지 갖춘 유일한 검증된 레이어이고,
OIDC IdP는 **계정 공유 자원**이라 지우면 blast radius가 우리 밖으로 나간다.

#### ⚠️ 계정 전제 — 공용 계정이다

- ⛔ **수동 정리는 반드시 태그(`*ref-dev*`)로 특정한다.** 이름만 보고 지우지 않는다.
- 📌 이 사실이 문서 요구사항을 하나 늘린다 — `03-new-project.md`를 **전용 계정 전제로 쓰지 않는다.**

|---|---|---|
| 1 | **Karpenter 노드는 IaC 밖** | EKS destroy 전에 NodePool 정리. 안 하면 orphan |
| 2 | `crds.keep: true` → **CRD 잔존** | `23 §2.5`가 명시한 설계. 수동 삭제 |
| 3 | **ENI 잔존으로 VPC destroy 지연** | EKS 완전 삭제 확인 후 VPC |
| 4 | S3 state 버킷은 **자기 state를 담는다** | 이번엔 L0 유지라 해당 없음 |
| 5 | ALB/TargetGroup | 실측 **0개** — 이번엔 해당 없음 |

> ⭐ **위 표 자체가 이미 산출물이다.** 현재 문서 어디에도 *"어떻게 지우는가"* 가 없다 —
> 고객사는 PoC가 끝나면 **반드시 지운다.** `06-runbooks.md`에 teardown 절차가 들어간다.
