# 문서 작성 규칙

**읽는 사람**: 산문을 쓰는 사람 전부. 문서든 코드 주석이든 같다.

두 절의 적용 범위가 다르다. **1절(구조)은 저장소 문서**(`docs/*.md` · 전역 `README.md` ·
루트 `CLAUDE.md`)에만 걸린다. "읽는 사람" 머리글과 400줄 제한은 문서를 가르는 장치라
코드에 성립하지 않는다(`variables.tf`가 590줄인 것은 변수가 많다는 뜻이지 쪼개라는 신호가
아니다). **2절(문체)은 사람이 읽는 산문 전부**에 걸린다. 범위는 2절이 적는다.

---

## 1. 구조 규칙

이 문서 집합이 다시 부풀지 않게 하는 장치다.

| # | 규칙 |
|---|------|
| 1 | **독자로 파일을 가른다.** 각 문서 첫 줄에 "읽는 사람"을 쓴다 |
| 2 | **변경 이력을 본문에 쓰지 않는다.** 이력은 각 모듈의 annotated git 태그 메시지(`git tag -n`)가 소유한다 |
| 3 | **이모지는 고정 어휘 7종만 쓴다.** 표 상태열: `✅ ⏳ ❌`. 본문 강조 4종: `⚠️`(경고) · `⛔`(금지/차단) · `🔴`(중대 발견·미판정) · `🔑`(핵심 통찰). 이 밖은 쓰지 않는다. 추가 강조는 볼드체 텍스트로 한다 |
| 4 | **한 문서는 400줄을 넘지 않는다.** 넘으면 독자가 갈린 것이다(데이터 카탈로그는 예외: `docs/naming/abbreviations/` 아래 전부) |
| 5 | **선택은 표로, 절차는 명령으로.** 산문으로 고르게 하지 않는다 |
| 6 | **문서 간 링크는 문서 단위.** 절 번호를 인용해야 하는 문서를 만들지 않는다 |
| 7 | **정정 서술을 남기지 않는다.** 문서는 현재 사실만 진술한다 |
| 8 | **결정은 스코프가 정한다.** 저장소 전역은 `docs/decisions.md`, 아키텍처마다 갈리는 것은 그 패턴 문서, 모듈 하나에만 걸리는 것은 그 모듈 코드(`variables.tf` description · `main.tf` 주석). 같은 이유를 두 곳에 쓰지 않는다 |
| 9 | **패턴 디렉터리는 `README.md`만 필수다.** 주제 문서는 그 주제가 400줄을 넘길 만큼 커질 때 나눈다. 클라우드 서비스를 이름으로 부르는 내용은 `<cloud>/` 아래에 둔다 |

**무엇을 결정으로 남기나**: 합리적으로 보여서 누군가 다시 제안할 법한데, 틀리면 비싼 것(재구축 ·
장애 · 보안)만 남긴다. 코드·테스트가 이미 막거나, 설계 문서 본문이 이유를 설명하거나, 한 번 겪으면
아는 운영 요령이면 남기지 않는다.

---

## 2. 문체 규칙

**적용 범위**: 사람이 읽는 산문 전부. 1절의 문서 집합에 더해 **코드·매니페스트의 주석과
산문형 값**(`.tf` 주석 · `variables.tf` description · GitOps 매니페스트 주석 · `Chart.yaml`
description · 셸 `echo` 문구)이 들어간다. 소비자가 읽는 면이면 파일 확장자로 가르지 않는다.

⛔ 범위 밖: 커밋 메시지와 태그 메시지. 그쪽은 사건 서술이 본업이라 기준이 다르다.

| # | 규칙 |
|---|------|
| 1 | 필러 표현을 없앤다. 도입부 헛기침·강조용 부사를 뺀다 |
| 2 | 정형화된 구조를 깬다. 이분법 대비·부정 나열·극적 단문·수사적 밑밥·가짜 행위 주체를 쓰지 않는다 |
| 3 | 능동태를 쓴다. 모든 문장에 실제 행위자를 세운다 |
| 4 | 구체적으로 쓴다. 막연한 단정과 "항상"·"절대" 같은 극단어 대신 대상을 짚는다 |
| 5 | 독자를 현장에 둔다. 3인칭 관찰자 시점 대신 구체적 상황으로 쓴다 |
| 6 | 리듬을 바꾼다. 문장 길이를 섞는다 |
| 7 | 독자를 믿는다. 사실을 바로 말하고 완충·정당화 표현을 뺀다 |
| 8 | 인용구처럼 들리는 문장을 다시 쓴다 |
