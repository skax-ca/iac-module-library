# Session — iac-module-library

## 지난 세션 (2026-09-12)
발표자료(`.local/notion/v0.2/`, git 미추적) 13~15장을 리뷰하고 고쳤다. 14장은 "목표·수단·기준"
3요소 병렬 구조가 실제로는 2+1 구조(①②는 이식 성공 여부, ③은 독립 판단)라 소개 문장을
판단 순서대로 풀어썼고, "수단"을 "방법"으로 전 구간 치환했다. 15장은 Azure 상위 스코프
RBAC을 왜 안 썼는지가 빠져 있어 카드를 새로 넣고 재구성했다.

15장 근거 검증 과정에서 두 가지를 바로잡았다. 처음에 "단일 구독 hub-spoke는 권장 구성이
아니다"라고 근거 없이 썼는데, Azure 아키텍처 센터가 단일 리소스 그룹 예제를 제시하고 구독
분리를 선택지로 설명해 **틀린 주장**이었다. 실제 근거는 CAF 「Management groups」 설계 영역의
"관리 그룹 스코프 RBAC 할당 비권고(과다 권한·상속 위험)"이고, 플랫폼 팀 예외는 PIM 전제라
워크로드 ID로 인증하는 ArgoCD에는 적용되지 않는다. 이 근거로 문구를 교체하고 출처 줄을 달았다.

`aks-reference-infra`의 role assignment 스코프를 넓히는 안을 검토했으나 인프라는 손대지
않기로 했다. `bootstrap/verify.sh`(29~35행)에 2026-08-27 실측 후 관리 그룹 스코프를 기각한
기록이 있고, hub/spoke가 서로 다른 구독이라 구독 스코프만으로는 N-spoke 문제가 안 풀린다.

문체 기준도 정리했다. 수사 대신 사실 서술, 규범적 주장은 공식 문서 확인 후 출처 명기,
`허브/스포크`는 패턴명(`허브-스포크`)만 한글로 두고 환경·역할 지칭은 `hub`/`spoke`로 통일
(슬라이드 26곳·md 31곳). 앞의 두 기준은 auto memory에 저장했다.
