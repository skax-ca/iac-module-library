# 세션 기록 규칙 (5개 저장소 공용)

세션은 이 저장소에서 열고 배포·GitOps 저장소 4개를 `--add-dir`로 붙인다. `.claude/session.md`는
**이 저장소 것 하나**가 5개 저장소의 기억이고, 형제 저장소에는 session.md를 두지 않는다.
전역 session-start·session-end 스킬의 두 절(`지난 세션`·`다음 할 일`)에 더해 아래 절을 갖는다.

## `## 저장소 상태` 절

`지난 세션` 앞에 둔다. 열은 `repo | git | 상태`. 행은 형제 4개(`eks-reference-infra`·
`eks-platform-gitops`·`aks-reference-infra`·`aks-platform-gitops`, 경로는 `../<repo>`).

- `git`: 브랜치와 원격 차이·미커밋 수를 한 토막으로(`main = origin`, `main = origin +1 미푸시`,
  `feat/x, 미커밋 2`).
- `상태`: 인프라 구축·철거 여부와 그 저장소의 다음 작업이 전제하는 사실 한 줄. 커밋 메시지가
  이미 갖는 작업 서술은 쓰지 않는다.

## 세션 시작 (스킬 3단계에 추가)

표의 각 repo에서 `git status -sb | head -1`과 `git status --short | wc -l`을 찍어 `git` 열과
대조한다. 어긋나면(다른 세션이 커밋·전환했거나 미커밋이 남았으면) 표를 고치지 말고 사용자에게
알린다. 표는 캐시이고 실물이 우선이다.

## 세션 종료 (스킬 1·2·4단계에 추가)

- 1단계 변경 확인 대상에 표의 repo 4개를 포함한다.
- 2단계에서 덮어쓸 때 `## 저장소 상태` 표를 보존하고 `git` 열을 실물로 갱신한다. `상태` 열은
  이번 세션에 바뀐 사실만 고친다.
- 4단계 커밋·푸시 대상에 변경이 있는 형제 repo를 포함한다. 형제 repo의 문서 전용 변경은 그
  repo 규칙대로 main 직접 커밋이다.
- `다음 할 일` 항목은 `[module]`·`[eks-ref]`·`[aks-ref]`·`[*-gitops]`·`[local]` 접두어로 어느
  저장소 일인지 적는다.

## `## 다음 할 일`의 네 소절

이 저장소군은 클러스터를 세웠다 걷어내며 쓰므로, 할 일의 절반이 **그때만 확인 가능**하다.
평평한 목록으로 두면 지금 되는 것과 재구축을 기다리는 것이 섞여 매 세션 다시 골라야 한다.
소절로 갈라 둔다.

| 소절 | 무엇이 들어가나 |
|------|----------------|
| 1·2. `<클라우드> 구축·철거와 같이` | 클러스터가 없으면 확인 자체가 불가능한 것. 재구축 순서대로 절을 놓고, 절 안은 `구축 전`·`구축 중`·`구축 후`로 나눈다 |
| 3. `재구축과 무관 — 아무 때나` | 문서·게이트·로컬 정리처럼 클라우드를 안 건드리는 것 |
| 4. `조건이 오면 (지금 하지 않는다)` | 트리거가 와야 열리는 것(태그 컷·차트 올림·작업자 증가)과 ⛔ 기각 근거 |

- 재구축 순서가 바뀌면 1·2절의 클라우드 이름을 바꾼다. 절 번호는 순서를 뜻한다.
- 두 클라우드에 공통인 실측(승인 흐름 등)은 **먼저 하는 쪽**에 전문을 두고, 나중 쪽에는
  "차이만 본다"로 적는다. 같은 항목을 두 번 적지 않는다.
- 끝난 항목은 지운다. 4절 항목은 조건이 오지 않으면 남아 있는 것이 정상이다.
